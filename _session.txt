     Editor de nodos Three.js — JSON config, colores por tipo y pan de canvas

     Contexto

     nodes.html ya es un prototipo funcional (Three.js + OrthographicCamera)
     con:
     - NodeView: caja con cabecera de color, filas de puertos in/out.
     - Cable: cuerda con física tipo verlet + relajación de distancias (ya da el
     efecto de "gravedad/balanceo" pedido) + un mesh de "enchufe"
     (makePlugMesh) en la punta.
     - Drag de nodos y creación de cables arrastrando de un puerto verde a uno
     rojo.

     Falta para cumplir lo pedido:
     1. Los nodos están hardcodeados en JS (5 llamadas a new NodeView({...})
     seguidas de conexiones a mano). Se pide poder configurar nodos vía JSON.
     2. El color de la punta del cable/enchufe es siempre gris oscuro fijo — se
     pide que sea el color asignado a ese puerto/nodo (como en la imagen de
     referencia: verde=mesh, magenta=vector/transform, rojo=escalar,
     azul=normal/coordenada, amarillo=textura).
     3. El canvas no se puede desplazar (pan) — solo se pueden mover nodos
     individuales.
     4. El "balanceo por gravedad" del cable ya existe (verlet + gravedad -0.55
     en Y + constraint solver) — se deja igual, solo se revisa que se vea bien
     tras los demás cambios.

     No hay build system ni framework: todo vive en un único archivo HTML con
     <script type="module"> que importa Three.js desde CDN. La solución se
     mantiene igual de autocontenida.

     Diseño del JSON

     Un bloque <script type="application/json" id="node-config"> embebido en el
     propio HTML (evita problemas de CORS/fetch sobre file://, y sigue siendo
     JSON real editable a mano). Forma:

     Cambios en nodes.html

     1. Bloque de config JSON: añadir <script type="application/json" 
     id="node-config">…</script> con el contenido de arriba; parsear con
     JSON.parse(document.getElementById('node-config').textContent) al arrancar.
     2. NodeView.makePort: en vez de recibir un color fijo por kind
     (in=rojo/out=verde hardcoded), recibe el type de la fila y resuelve el
     color con portTypes[type] ?? (kind === 'out' ? DEFAULT_OUT : DEFAULT_IN)
     (los defaults actuales rojo/verde se mantienen como fallback para filas sin
     type, igual que en la imagen donde la mayoría de inputs sueltos son
     rojos). Guardar el color resuelto en g.userData.port.color para que Cable
     lo reutilice.
     3. NodeView constructor: pasa row.type a makePort; añade un helper
     getPort(label, kind) que busca en inPorts/outPorts por label (necesario
     para resolver los edges del JSON por nombre en vez de por índice).
     4. buildGraph(config) (nueva función, sustituye el bloque actual de new 
     NodeView(...) x5 + 4 cables.push(new Cable(...)) manuales):
       - Crea un Map<id, NodeView> instanciando cada graph.nodes[i] a partir de
     nodeTypes[node.type] + x/y.
       - Para cada graph.edges[i], resuelve fromNode.getPort(fromLabel, 'out') y
     toNode.getPort(toLabel, 'in') y crea new Cable(outPort, inPort).
       - Devuelve { nodes, cables } para que el resto del código (raycasting,
     animate loop) siga igual.
     5. Cable: constructor recibe el color desde startPort.userData.port.color
     (el puerto de salida define el color del cable, como en la imagen donde el
     cable hereda el color de su origen). Usarlo en LineBasicMaterial({ color })
     y pasarlo a makePlugMesh(color).
     6. makePlugMesh(color): el cuerpo del enchufe (body) se pinta con color en
     vez de 0x111114 fijo; las clavijas (prong1/2) y el cable corto (cord) se
     mantienen oscuros para que se lea como un enchufe real con la carcasa
     coloreada — mantiene la forma pedida ("como un enchufe pequeño") pero con
     el color de tipo de dato/nodo de origen.
     7. Pan de canvas (feature nueva, no existía):
       - En pointerdown: si hitTest no golpea ningún nodo/puerto (canvas vacío)
     y no se está creando un cable, entrar en modo pan: guardar panStart = {x: 
     e.clientX, y: e.clientY} y camStart = camera.position.clone().
       - En pointermove: si panning, convertir el delta de píxeles a unidades de
     mundo usando el tamaño del frustum ortográfico
     ((camera.right-camera.left)/innerWidth,
     (camera.top-camera.bottom)/innerHeight) y mover camera.position.x/y
     (invertido en Y). El raycaster ya usa camera.matrixWorld, así que
     screenToWorld/hitTest funcionan sin cambios adicionales.
       - En pointerup: salir de modo pan.
       - Cursor: grab por defecto sobre el canvas vacío, grabbing mientras se
     hace pan (CSS simple en renderer.domElement).
       - Añadido opcional de bajo costo: zoom con rueda del ratón ajustando
     camera.zoom (clamped, p.ej. 0.4–2.5) + updateProjectionMatrix(), ya que es
     un complemento natural al pan en un editor de nodos y no añade complejidad
     relevante.
     8. Gravedad de cables: no se toca la lógica de Cable.update() (verlet +
     constraint solver ya simulan el balanceo); solo se revisa visualmente tras
     los cambios de color/plug por si hace falta ajustar la constante de
     gravedad (-0.55) o el damping (0.92).

     Verificación

     - Abrir nodes.html directamente en el navegador (open nodes.html) — sigue
     sin necesitar servidor porque Three.js se importa desde CDN y el JSON está
     inline (no hay fetch a archivo local).
     - Comprobar visualmente: los 9 nodos del JSON aparecen con la
     disposición/colores de cabecera esperados y las conexiones iniciales ya
     trazadas.
     - Arrastrar un nodo: el resto de cables conectados a él deben seguirlo y
     seguir "colgando" con balanceo.
     - Crear un cable nuevo arrastrando desde un puerto de salida
     (verde/magenta/azul/amarillo según tipo) hasta un puerto de entrada rojo:
     el cable y el enchufe de la punta deben tomar el color del puerto de
     origen.
     - Pan: hacer click y arrastrar sobre una zona vacía del canvas mueve todo
     el grafo; soltar y volver a arrastrar un nodo o crear un cable debe seguir
     funcionando con las coordenadas correctas (sin desfase) después de haber
     paneado/zoomeado.
     - Redimensionar la ventana: el listener de resize existente debe seguir
     recalculando el frustum sin romper el pan/zoom aplicado.
